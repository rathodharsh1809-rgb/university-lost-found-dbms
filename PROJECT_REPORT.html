1. Introduction

In a modern university ecosystem with thousands of active students, faculty members, and campus visitors, personal belongings such as student identification cards, laptops, headphones, lab manuals, and keys are routinely misplaced. Traditional lost and found methods rely on physical lost notice boards, chaotic social messaging threads, or paper logbooks. These manual processes result in low recovery rates, prolonged delays in returning items to owners, and heavy administrative overhead for campus security checkpoints.

To resolve this problem, the University Lost & Found Management System was built as an enterprise-grade, database-driven web platform. It delivers self-service lost reporting, real-time catalog browsing, automated claim matching, and an executive telemetry dashboard providing visual analytics on campus recovery performance. Prompt engineering and advanced AI coding agents were harnessed across all project milestones—including Three-Level Architectural separation, schema aggregation query formulation, Chart.js multi-view data visualization, and automated integration test authoring.

2. Target User

The application is engineered for four primary stakeholder profiles within the university:

  • Students: Need a clean, friction-free interface to file lost item reports with specific location and time markers, browse found inventories, and track the status of their belongings.
  • Faculty & Campus Staff: Frequently locate items left behind in lecture halls, laboratories, or seminar rooms and turn them over to security desks.
  • Lost & Found Department Officers: Manage physical catalog shelves, update item availability (Available, Claimed, Disposed), review verification claims, and manage database records.
  • Campus Administration & IT Ops: Monitor institution-wide recovery rates, identify high-loss campus zones (hotspots), track notification dispatch queues, and audit physical SQLite database telemetry.

5. Application Design and Development

5.1 Three-Layer Architectural Flow

The system strictly avoids business logic or direct SQL queries in frontend presentation templates. Controllers in lost_found_routes.py handle HTTP requests and invoke domain functions in lost_found_service.py, which then executes optimized SQL queries via lost_found_repo.py.

[Browser Client] <== HTTP GET/POST ==> [Routes Layer (lost_found_routes.py)] || (Service Calls) v [Service Layer (lost_found_service.py)] || (Data Queries) v [Repository Layer (lost_found_repo.py)] || (PRAGMA WAL Queries) v [SQLite Database (lost_and_found.db)]

5.2 Relational Entity Schema

Table Primary Key Foreign Keys & Key Attributes Functional Role
USERS user_id email (UNIQUE), role (STUDENT, FACULTY, ADMIN) Stores registered campus accounts and notification recipients.
LOST_ITEMS lost_item_id user_id (FK), status (SEARCHING, FOUND, COLLECTED) Captures reports of missing belongings with date and location.
FOUND_ITEMS found_item_id status (AVAILABLE, CLAIMED, DISPOSED) Inventories items physically turned in to campus security.
NOTIFICATIONS notification_id user_id (FK), is_read Automated inbox alerting students when their items are found.

5.3 Core UI Modules

  • Executive KPI Grid: Summarizes total lost reports, active found inventory, institution recovery rate percentage, and locked/unlocked user counts.
  • Animated Charts: Real-time Chart.js doughnut with inner aggregate total, switchable to polar area or bar chart views.
  • Master Relational Tabs: Interactive table tabs with live instant searching across item descriptions, owners, and SQLite file storage metrics.

7. Conclusion

7.1 Project Summary

The University Lost & Found Management System successfully replaces outdated manual methods with an automated, transparent, and aesthetically engaging web portal. Operating on a lightweight SQLite engine with Write-Ahead Logging and a structured Python Flask backend, it delivers reliable data consistency, real-time analytics, and automated student alerting.

7.2 The Role of AI in Rapid Engineering

The integration of generative AI coding assistants and precise prompt engineering drastically accelerated development. Key achievements—including refactoring raw database queries into a production Three-Layer Architecture, creating animated multi-view Chart.js components, establishing automated integration test suites, and resolving 39 complex AST parser errors—were accomplished rapidly and reliably without introducing technical debt.

7.3 Future Improvements

  • AI Multimodal Image Matching: Integrate a computer vision model (e.g., CLIP / Gemini Vision) to automatically calculate visual similarity scores between lost and found item photos.
  • Automated SMS & Email Alerts: Connect Twilio / SMTP services to notify students the moment a matching item is logged by campus security.
  • QR Code Tagging: Provide students with printable QR tags for high-value belongings (laptops, backpacks) allowing one-scan owner notifications.
